# Parsing comparison fields

Each JSONL row follows `schema.json` and the existing `FieldItem` review model. `doc` is relative to the corpus root, `page` is one-based (omitted or null means page 1), and `expected` is one value on that page. `quote` is optional reviewer context only; scoring never uses it. The checked-in `synthetic-v1.jsonl` contains five demonstration items from the existing Northwind PDFs. They are explicitly unreviewed and are not the planned 150-field benchmark.

`scribe-eval parse-compare --fields <jsonl> --corpus <dir> --engines pdfplumber tesseract gemini --out <report.json>` extracts each unique document/page once per engine, then compares the expected field against whole-page text. The command writes JSON and Markdown reports. The measured report includes exact and normalized accuracy by engine and field kind, plus mean cost and latency per unique page with deterministic percentile bootstrap confidence intervals. It never turns field descriptions into inferred semantic extraction.

Scoring is type-aware. Exact presence is case-sensitive and whitespace-sensitive, with token boundaries so (for example) `10` does not match inside `100`. Normalized text and table cells fold case and collapse whitespace, while retaining token boundaries. Numbers remove thousands separators and compare decimal values plus a case-folded unit suffix; units are not converted. Dates normalize recognized ISO, slash, dash, and English month-name formats to ISO dates; ambiguous slash dates are interpreted month/day/year before day/month/year. Currency compares normalized amounts and ISO codes; `$`, `€`, `£`, `¥`, and `₹` map to USD, EUR, GBP, JPY, and INR. Currency codes and units are not converted. This is expected-value matching, not a field locator or a semantic extractor.

Non-dry-run commands refuse rows whose `reviewed` field is not exactly `true`, using the shared review guard. `--dry-run` validates the schema and safe corpus paths, writes a report with `measurement: false` and `NOT MEASURED`, and does not extract pages or call a provider.

The `pdfplumber` engine reads the PDF text layer. Tesseract uses the optional `parsing-eval` extra and the local Tesseract executable; neither is imported by the service. Gemini uses the existing Gemini 2.5 Flash OCR client on rendered page images. Its response cache uses model, prompt version, and image hash; cache hits are charged at $0. Before any extraction starts, the command estimates uncached Gemini page cost and asks the shared spend ledger to enforce the cap. Preflight budgets 8,000 image input tokens and an explicit 30,000 output-token allowance per page. These are conservative budget assumptions tied to the 30,000-character OCR page limit, not measured usage figures or provider guarantees. Actual cost is calculated from usage returned by the Gemini OCR response; missing token counts are estimated and marked in the page report and spend ledger. No provider call is made by tests.

The five demonstration fields are for command and review workflow examples only. Do not use their scores as published quality measurements. Real field rows must be drafted and reviewed separately before a measured run.
